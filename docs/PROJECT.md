# Achievement Companion - описание проекта

Документ для того, кто продолжает работу над проектом (человек или агент): зачем он, как устроен, что сделано,
что проверено, что нет, и что дальше. Пользовательская инструкция - в [README](../README.md).

Версия: 0.4.0. Автор: Даниил Л. (GitHub UsusCimex). Лицензия MIT, код SAM.API - zlib.

## 1. Идея

Десктоп-приложение под Windows для прохождения Steam-игр на 100%.

- Показывает все достижения игры: иконка, описание (включая скрытые), процент получивших, редкость, оценка времени.
- Само ведёт учёт: что открыто в Steam, подтягивается автоматически, в том числе во время игры.
- Ручная отметка "сделал, но не засчиталось" - для случаев, когда достижение реально выполнено, но в Steam
  не записалось (например, игра запускалась под чужим AppID).
- Запись в Steam как в SAM (Steam Achievement Manager): кнопка "В Steam" у достижения. Код SAM встроен.
- План до 100%: миссибл первыми, потом сюжет, прочее, гринд; группы "за один заход"; сколько осталось.
- Оверлей поверх игры без внедрения в неё: "не пропусти", "ближайшие", отметка в один клик.
- Поиск гайдов по конкретному достижению (Steam, обсуждения, YouTube, Google).

Пользователь - ачивхантер, идущий на 100%, или тот, кому нужно не пропустить миссибл и свести реально сделанное.

Сознательно не делаем: чтение памяти игры, DLL-инжект, хуки рендера (античиты, легальность).

## 2. Архитектура

```
AC.App (WPF, x64)  ----->  AC.Core (логика, net10.0, без Windows)
        |
        +----------->  AC.Infrastructure (хранилище, Steam Web API, файлы Steam, запуск помощника)
                                 |
                                 +--> Steam Web API (api.steampowered.com, store.steampowered.com)
                                 +--> локальный Steam: реестр, config/loginusers.vdf, appcache/stats/*.bin
                                 +--> AC.SteamBridge.exe (x86, SAM.API) --> steamclient.dll --> Steam-клиент
```

| Проект | Назначение | Ключевые файлы |
| --- | --- | --- |
| `src/AC.Core` | модели и вся логика, тестируется без Steam | `Models.cs`, `GameLogic.cs` (статусы), `KindClassifier.cs` (тип по тексту), `TimeEstimator.cs`, `SampleStats.cs` (своя статистика), `Planner.cs`, `AchievementQuery.cs` (фильтры, сортировки), `Exporter.cs`, `TagPack.cs` (файл разметки), `SteamFormats/` (бинарный KeyValues, схема, текстовый VDF) |
| `src/AC.Infrastructure` | ввод-вывод | `GameService.cs` (все сценарии), `SteamWebApi.cs`, `SteamLocal.cs` (реестр, файлы, слежение за файлом статистики), `BridgeClient.cs`, `JsonStore.cs`, `Settings.cs`, `Dpapi.cs`, `CompletionTimeSource.cs` (completionist.me) |
| `src/AC.SteamBridge` | короткоживущий помощник: `read`, `unlock`, `lock` через Steam-клиент, ответ JSON в stdout | `Program.cs`, `SAM.API/` (копия из gibbed/SteamAchievementManager) |
| `src/AC.App` | интерфейс WPF, тема Fluent (светлая/тёмная по системе) | `MainWindow.xaml`, `MainViewModel.cs`, `AchievementRowViewModel.cs`, `OverlayWindow.xaml`, `SettingsWindow.xaml`, `Native.cs` (горячие клавиши, стили окна), `Converters.cs` |
| `tests/AC.Core.Tests` | 20 тестов: консольный раннер без пакетов | `Program.cs` |

Внешних NuGet-пакетов нет (MVVM, тесты, DPAPI, парсеры написаны в проекте).

### Почему помощник отдельный

SAM.API грузит 32-битный `steamclient.dll` и выставляет `SteamAppId` процессу: один процесс = одна игра.
Поэтому помощник запускается на каждую операцию и сразу выходит. Пока он жив, друзья видят тебя "в игре".
Собирается self-contained win-x86, чтобы не требовать x86 .NET.

## 3. Данные

Папка `%LocalAppData%\AchievementCompanion\`:

| Файл | Что внутри |
| --- | --- |
| `games/<appid>.json` | схема (имя, описание, hidden, иконки, % Steam, % по выборке, protected), состояния (открыто в Steam, время, ручная отметка, заметка), разметка (тип, источник auto/manual, группа), оценки времени, ручные оценки, очередь на запись, своё время в игре, данные выборки |
| `settings.json` | API-ключ (зашифрован DPAPI), SteamID64, язык, перцентиль, режим записи, источник статуса, горячие клавиши, оверлей |
| `library.json` | кеш библиотеки |
| `unlock_log.jsonl` | журнал записей в Steam: время, appid, api-имя, unlock/lock, результат |

## 4. Источники данных

| Что | Откуда | Заметки |
| --- | --- | --- |
| Схема достижений | `ISteamUserStats/GetSchemaForGame/v2` (ключ) + локальный `appcache/stats/UserGameStatsSchema_<appid>.bin` | у скрытых Web API не отдаёт описание, локальная схема отдаёт; там же флаг "защищено" (permission & 3) |

| Своя статистика | авторы обзоров `store.steampowered.com/appreviews/<appid>` + их `GetPlayerAchievements` | проценты и время к каждому достижению; см. раздел 5 |

## 5. Как считается время

Приоритет для каждого достижения: своя оценка > замер по выборке > модель по редкости.

- **Модель по редкости.** Время от начала игры t = T * ln(maxPct / pct) / ln(maxPct / minPct), где T - время до 100%.
  Частое достижение - около 0, самое редкое - T. P75 и P90 - запас x1.3 и x1.7.
- **Время до 100% (T).** Приоритет: вручную / completionist.me > медиана по выборке > вывод из своего прогресса
  (наиграно / доля шкалы самого редкого из полученных; нужно от 30 минут и не самое частое достижение).
- **Выборка (`SampleStats`).** До 300 авторов обзоров, пока не наберётся 80 открытых профилей. У каждого известны
  время открытия достижений и две точки "момент - наиграно" (на обзоре и всего на последнем запуске).
  Между ними считаем игру равномерной, от 0 в момент первого открытия. Процент = доля выборки.
  Минус: авторы обзоров играют больше среднего, а время до первого достижения не учитывается.
- **Своё время в игре.** "Реально наиграно" заменяет время Steam; "не считать" вычитается (AFK, до появления достижений).

### Известные ограничения и что проверить

1. v0.4 (шапка с артом, выборка, гайды) не собиралась на Windows - первая сборка может дать ошибки.
2. Выборка: сколько у авторов обзоров открытых профилей - зависит от игры; если мало, проценты будут шумными.
3. Оверлей не виден в эксклюзивном полноэкранном режиме игры (только оконный и borderless).
4. Разбор completionist.me зависит от их вёрстки.
5. При запуске через `dotnet build` у пользователя не появился `AchievementCompanion.exe` (запускали через `dotnet ...dll`);
   причина не выяснена, релизная сборка через `dotnet publish` даёт exe.
6. Только Windows: WPF. Для Linux/macOS нужен переезд на Avalonia (обсуждали, решили пока не делать).

## 7. Идеи на будущее

- Сбор выборки в фоне и её обновление раз в неделю.
- Импорт гайдов и списков миссибл в файл разметки (`TagPack`), показ текста гайда в приложении.
- Свой поток игроков для выборки помимо обзоров (друзья, группы).
- Уведомление при пропуске миссибл (например, глава закончилась, а миссибл не получен).
- Переезд на Avalonia для Linux и macOS.
